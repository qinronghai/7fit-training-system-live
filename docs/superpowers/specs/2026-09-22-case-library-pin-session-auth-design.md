# 7Fit 案例库短 PIN 设备会话认证设计

## 目标

让馆主首次输入短 PIN 后，在可信设备上保持后台会话，之后上传和编辑案例不再重复输入长管理密钥；公开访客继续只能查看已发布案例。

## 当前基线

- GitHub Pages 前端位于 `assets/real-results/`，主要后台逻辑在 `patch.js`。
- 前端当前从 `localStorage` 读取 `7fit_case_admin_key`，并以 `x-admin-key` 请求 Supabase Edge Function `case-api`。
- `list` 为公开读取；后台验证、保存和图片上传由 Edge Function 保护。
- Edge Function 源码当前不在 GitHub 仓库中，不能只改前端，否则会留下旧接口和安全边界。

## 方案

采用“6 位 PIN 作为登录引导 + 服务端签发设备会话”的方案：

1. 访客访问案例库时不显示后台操作控件。
2. 馆主通过“馆主登录”输入 6 位 PIN。
3. Edge Function 在服务端验证 PIN，PIN 只保存在 Supabase Secret 的哈希或等价安全配置中，不返回给浏览器。
4. 验证成功后签发随机设备会话 Token，只在数据库中保存 Token 哈希；前端只保存会话，不保存 PIN。
5. `save-case`、`upload`、编辑相关操作都必须校验未过期且未撤销的会话 Token。
6. 登出时清除本地会话，并由服务端将对应会话标记为已撤销。

## 会话与安全约束

- 默认设备会话有效期 30 天；登出立即清除本地会话。
- 会话表只允许 Edge Function 使用服务端角色访问，`anon` 和 `authenticated` 不直接访问会话表。
- PIN 错误尝试按设备/IP 进行限流，连续 5 次失败后暂时锁定。
- PIN 不写入 URL、localStorage、日志、错误信息或网络响应。
- 不再将 `x-admin-key` 作为长期后台凭证；迁移期间如需兼容，必须有明确的临时开关和移除步骤。
- 公开 `list` 不需要登录；后台写操作必须服务端鉴权，不能只依赖前端隐藏按钮。
- 浏览器端不得出现 Supabase `service_role` 或其他服务端密钥。

## 页面行为

未登录时显示“馆主登录”；登录后显示“馆主后台 · 已登录”“上传案例”“退出登录”。登录失效时回到登录入口，并显示“登录已过期，请重新验证”，不能弹出长密钥输入框。

## 范围外

- 不引入多角色后台、手机号登录、短信验证码或复杂用户管理。
- 不改变公开案例内容、案例数据结构或案例详情视觉布局，除非接口迁移要求最小兼容调整。
- 不直接修改线上 `master`、不直接部署 Edge Function，除非完成测试并获得发布授权。

## 完成标准

- 未登录访问案例库和公开 `list` 正常。
- 正确 PIN 只需输入一次即可完成上传和编辑。
- 刷新页面、重新打开页面时，会话在有效期内仍然可用。
- 退出登录后上传和编辑被拒绝，页面只保留公开浏览。
- 错误 PIN 被限流，且不会泄露正确性以外的敏感信息。
- 前端、Edge Function、浏览器测试均不再依赖 `7fit_case_admin_key`。
